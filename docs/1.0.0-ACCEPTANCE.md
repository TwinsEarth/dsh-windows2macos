# What 1.0.0 would have to prove — a draft for objection

**Status: DRAFT, and deliberately incomplete.** Nothing here is an announcement that 1.0.0 is close. This file
exists because the goal names three properties — **分模块 / 分层级 / 分权限** — and a version number means
nothing without a definition that can fail. It is written to be argued with, and every row says **where the
claim is checked and whether that check can actually fail**.

The rule applied throughout: **a criterion that nothing measures is not a criterion.** Where a check exists
but has no caller, that is stated in its own column rather than hidden behind a tick.

**Every criterion carries one of three statuses, decided by a rule rather than by opinion** — **ENFORCED**
(the pre-flight goes red without it), **MEASURED** (something checks and prints, and the run stays green), or
**UNVERIFIED**. **MEASURED is not ENFORCED**, and §4 says how to tell them apart in one command.

**The statuses in §4 are themselves checked.** `test/acceptance-doc.test.mjs` reads the pre-flight's own
`DECLARED_CHECKS` list and fails if this document names a check that does not exist — so a criterion cannot
silently become unenforced while this file keeps claiming otherwise. **A document that restates what a check
does is a second source of truth unless something binds the two together.**

## 1. 分模块 — modules with a declared identity

| # | Criterion | Checked by | Enforced? |
|---|---|---|---|
| 1.1 | Every source module belongs to exactly one declared layer | `scripts/layer-check.mjs` | **yes** — `clean: every cross-layer edge is declared` |
| 1.2 | Every dependency edge is declared, and every declared edge is used | `scripts/layer-check.mjs` | **yes** |
| 1.3 | Every suite on disk is named by a script | pre-flight `test wiring`, `claims` | **yes** — reported, not silently ignored |
| 1.4 | Every document's claim about the artifact matches the artifact | `test/claims.test.mjs` | **yes** — 48 claims, and it has caught real drift |
| 1.5 | No module is unreachable — every declared thing has a caller | `scripts/reachability-check.mjs`, `reachability-classify.mjs` | **MEASURED, not enforced — see below** |

`1.5` is the row that mattered most and the one that went unsatisfied longest. This span shipped three
mechanisms that were, for a round each, fully tested and completely uncalled: `field-authority.mjs`,
`approval-gate.mjs`, and before them `createApprovalIndex`. **A tested mechanism with no caller is
indistinguishable from a finished feature by reading either the tests or the source.** `1.4` catches
*documentation* drift and cannot catch this, because the document and the code can agree while neither is
reachable.

**0.35.0 measures it.** `scripts/reachability-check.mjs` matches **imports** — a module and a name together —
and reports exports that only test files import.

### Why it is a report and not a gate, which is the honest part

Measured against this repository it names **465 exports**, and it **cannot tell three kinds apart**:

1. **the defect** — built, tested, never wired;
2. **a deliberate surface** — the plugin's entry points and re-exports;
3. **composition** — a capability reached only through another module's use.

Only the first is a finding. **A check that fails on 465 things nobody will fix is a check that gets
disabled within a week, and a disabled check is worse than none because it is cited as coverage.** So it exits
**0** and prints, and its own output says *"READ THIS AS A LIST TO TRIAGE, NOT A LIST OF BUGS."*

The tests therefore build **synthetic trees where ground truth is known** and pin the one distinction it *is*
reliable for — including the false positive that broke the first version, `deepEqual` from
`src/relay/state.mjs` appearing to be named by **69 test files** that were all calling `assert.deepEqual`.

**So `1.5` is measured, not closed.** A defect of this class is now *visible*; it is not *prevented*, and
nothing in the pre-flight fails when one appears.

### What the classification found, and what it reported about itself

`reachability-classify.mjs` sorts the findings by **the shape of the import graph** rather than by name. The
shape that identified the two known defects was: **one export, one importer, and that importer is the test
named after the module** — a closed loop, where nothing in the program reaches the code.

Against this repository: **468 findings, 316 `sibling-imported`, 91 `closed-loop`, 61 `same-module`.**

**The 91 is not a defect count, and the classifier says so in three pinned tests.** It cannot see a
**dynamic import** (`await import('./x.mjs')` names no binding) and it cannot see a module reached only because
a **CLI entry point spawns it** — which is every file in `scripts/`, and is why that number is large. Both
limits are asserted rather than commented, because a classifier whose limits are undocumented gets trusted
past them.

**Investigating one finding by hand found a real defect that the count had buried**: `src/agent/council.mjs`
declared its own `export const AUTHORITY_MAX = 100` instead of importing the bound from `authority.mjs`.
**Two copies of a limit that nothing can keep in step, failing silently** — raise the real maximum and this
module keeps refusing `101` while naming the wrong number as authoritative. It now imports it.

### `v4.10.0`'s council was BUILT AND NOT ROUTED — **fixed in 0.37.0**

`reachability-classify` reported `src/agent/council.mjs` as a closed loop, and reading it to check that
confirmed the finding: **275 lines implementing committee governance, imported by nothing but its own suite.**
`v4.10.0` is marked *shipped in 0.11.0* in `ROADMAP.md`, and **0.30.0 verified its three falsifying tests are
asserted by name** — which they are. **What was never checked is whether anything routes a question to it.**

**This was the same defect as `field-authority` and `approval-gate`, in a third module** — the one the
reachability work was built to find.

**`w2m_council` now routes it.** The state lives in `createCouncilSessions` because a council walks **seven
phases across many calls** and one held inside a single invocation **could never finish**. Every read of a
decision returns the **dissent with its reasons** and a **`recount`**, so v4.10.0's third falsifying test —
*"a decision with recorded dissent is retrievable with the dissent"* — holds **after the council that produced
it is gone**, which is a property of the session rather than of the decision. Both are tested.

**A tie is still refused, not broken**, and the tool does not paper over it: a split council is the one case
where the council exists to escalate to a person.

## 3. 分权限 — declared capabilities, and something that consults them

| # | Criterion | Checked by | Enforced? |
|---|---|---|---|
| 3.1 | Capabilities declared with a cost and a destructiveness flag | `authority.mjs` (`CAPABILITIES`) | **yes** |
| 3.2 | Every declared capability is reachable by some band | `auditCapabilities()`, asserted | **yes** |
| 3.3 | A decision is reached from a real dispatch's own facts | `gateDispatch`, `capabilityForDispatch` | **yes** |
| 3.4 | The dispatch path consults it | `tools.mjs`, asserted end to end | **yes** — since 0.23.0 |
| 3.5 | An undeclared capability is refused, not granted or escalated | `permission.test.mjs` | **yes** |
| 3.6 | Escalation is exactly one band | asserted across the whole table | **yes** |
| 3.7 | Nothing destructive auto-settles, at any level | `mayAutoSettle`, asserted | **yes** |
| 3.8 | An escalated dispatch reaches a queue an approver can answer | `w2m_approvals`, asserted end to end | **yes** |
| 3.9 | The queue's front door meters **raising only** | `approval-gate.mjs`, wired in 0.31.0 | **yes** |
| 3.10 | Field-level memory acceptance is driven by the same model | `field-authority.mjs`, called by `w2m_memory` since 0.41.0 | **yes** — the caller arrived six versions after the mechanism |
| 3.11 | **The gate is ON by default** | `requireAuthorityLevel`, asserted | **NARROWED — see below** |
| 3.12 | A level is chosen by name, never typed | `authority-choice.mjs`, asserted | **yes** |
| 3.13 | A misconfigured level is reported, not silently ignored | `w2m_status.actor_authority` | **yes** |

### `3.11` — narrowed rather than closed, and the distinction is stated

`actorAuthorityLevel` is **unset by default**, and an unset level means the gate reports `enforced: false` and
changes nothing. So a default install dispatches exactly as it did before the permission model existed.

**0.34.0 adds `requireAuthorityLevel`** (or `W2M_REQUIRE_AUTHORITY_LEVEL`), which closes it for a machine that
asks for it to be closed. Measured, the whole table:

| `requireAuthorityLevel` | level | result |
|---|---|---|
| off | unset | **starts**, gate unenforced |
| off | chosen | starts, gate enforced |
| **on** | **unset** | **refuses to start** — `AUTHORITY_CHOICE_NOT_CHOSEN` |
| **on** | **unusable** | **refuses to start** — `AUTHORITY_CHOICE_UNKNOWN` |
| on | chosen | starts, gate enforced |

**Why it is opt-in, which is a deliberate limit rather than a hedge.** Refusing unconditionally would be the
honest reading of *"a permission system that is off is untested in production"* — and it would also **stop
every machine running an earlier version the moment it upgraded**, because none of them has a level. That
trades one silent failure for a loud outage, and **an outage is not a security property.**

**So the gap is narrowed, not closed.** A fleet that does not set this flag is exactly as unenforced as
before, and this document says so rather than letting the flag's existence imply otherwise. **The remaining
question for 1.0.0 is whether shipping a flag is enough, or whether the default must flip** — and that is a
decision about who this release is for, not a defect to fix.

## 4. The status of every criterion, in three values

**One rule decides the status, and it is checkable rather than a matter of opinion:**

| Status | What it means | How to tell |
|---|---|---|
| **ENFORCED** | the pre-flight **fails** if this stops being true | delete the thing and run `scripts/preflight.mjs`; it goes red |
| **MEASURED** | something checks it and **prints**, but the run stays green | the check exists and exits 0 either way |
| **UNVERIFIED** | nothing checks it, or the check cannot see this | there is no check, or its own documentation says it cannot |

**MEASURED is not ENFORCED**, and this project has already paid for confusing them: the reachability classifier
named **465 exports** and could not say which were defects, so a gate built on it would have been turned off
within a week. **A check that cannot fail is a report.**

### ENFORCED — the pre-flight goes red without it

| # | Criterion | The gate |
|---|---|---|
| 1.1 | every module belongs to exactly one declared layer | `layer-check` |
| 1.2 | every dependency edge is declared, and every declared edge is used | `layer-check` |
| 1.3 | every suite on disk is named by a script | `test wiring` |
| 1.4 | every document's claim about the artifact matches the artifact | `claims`, 48 claims |
| **1.5** | **no orphan module without a written reason** | **`reachable or accepted`** — **7 orphans, 65 exports, down from 8 and 72** |
| 2.1–2.4 | ranked layers, an allow-list of edges, no upward edge | `layer-check` |
| 3.2 | every declared capability is reachable by some band | `auditCapabilities`, asserted |
| 3.4 | the dispatch path consults the gate | `tools.test.mjs`, end to end |
| 3.5 | an undeclared capability is refused | `permission.test.mjs` |
| 3.6 | escalation is exactly one band | asserted across the whole table |
| 3.7 | nothing destructive auto-settles | `mayAutoSettle`, asserted |
| 3.9 | the queue's front door meters raising only | `approval-gate.test.mjs` |

| 5.1 | the packed tarball registers all eleven tools | `packed tarball` |

|---|---|---|

## 5. Claims this work corrected, kept rather than tidied away

A document that only shows its final state hides how it got there, and **every entry below was a statement that
was written down, acted on, and later found wrong.** They are kept because the pattern is the finding: four of
the seven were **a claim about wiring or delivery that a single check disproved.**

| Claim | Where it was made | What checking found |
|---|---|---|
| "v4.8.0 shipped, suite verified on MacMini" | `ROADMAP.md` | the block and lineage are real; **"per-field acceptance driven by the authority model" was never built** — `blocks.mjs` did not import `authority.mjs` at all |
| "the already-shipped rate limiter as its front door" | `ROADMAP.md`, v4.9.0 | **never built** — `approval-index.mjs` imports `authority.mjs` and nothing else |
| "**the connection now exists**" | CHANGELOG 0.29.0, of `field-authority` | **it exists inside that module and nowhere else.** Nothing imports it; it is an accepted orphan today |
| "v4.10.0 shipped in 0.11.0" | `ROADMAP.md` | the three falsifying tests **are** asserted — and **nothing routed a question to it.** Fixed in 0.37.0 by `w2m_council` |
| "zero is the all-clear" | `machine-test-packet.mjs` | false for every count but one; **zero means every file was ABSENT** — a total failure read as a clean run |
| "the eight suites failed on MacMini because of `node_modules`" | CHANGELOG 0.32.0 | recorded as a hypothesis then, **and measured in 0.38.0**: `council.mjs` runs there because it needs nothing, so the suites fail on **what their fixtures reach for** |
| "`log-bounds` fixes the 40× log growth" | CHANGELOG 0.12.0 | the module is correct and tested; **nothing calls it.** It is on the accepted-orphan list as `interface-unrouted` |

**Two of these seven were corrected by the same instrument** — the reachability classifier, which was built
*because* the first two had happened. **That is the only argument for a check that this project accepts: it
found something the previous three rounds had missed.**

## 6. What would make this file finished

1. **Flip §3.11's default.** `requireAuthorityLevel` exists and is tested; whether 1.0.0 ships with it on is a
   decision about who the release is for. **A permission system that is off is one that has never run.**
2. **Wire the remaining three `interface-unrouted` orphans**, or delete them. `health` is the sensor the user
   asked for by name; `log-bounds` is the answer to a measured 40× growth; `storage` holds the undelatable
   tiers. **Each is on the list with what would remove it.**
   ~~`field-authority`~~ **was the fourth and is DONE — 0.41.0 gave it the caller its entry named.** It is
   worth noting what removed it: **not a decision to tidy up, but the gate's stale-entry check going red** the
   moment something imported the file. The list policed itself.
3. **Re-run the 69 unverified suites on MacMini**, which needs `node_modules` there — an environment change
   nobody has made.
4. **Promote every MEASURED row to ENFORCED**, so this document stops being a parallel list that can drift from
   the pre-flight. **A document that restates what a check does is a second source of truth, and this project
   has already paid for one of those.**

**This file is honest about being unfinished, which is the only useful thing a 1.0.0 definition can be before
1.0.0 exists.** The question it was written in answer to — *write the acceptance definition, or keep advancing
the roadmap?* — was asked in round 12 and answered by writing it. **Whether to act on items 1–4 is a decision
the person who owns this repository still has to make.**
