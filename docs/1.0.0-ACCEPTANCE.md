# What 1.0.0 would have to prove — a draft for objection

**Status: DRAFT, and deliberately incomplete.** Nothing here is an announcement that 1.0.0 is close. This file
exists because the goal names three properties — **分模块 / 分层级 / 分权限** — and a version number means
nothing without a definition that can fail. It is written to be argued with, and every row says **where the
claim is checked and whether that check is actually running**.

The rule applied throughout: **a criterion that nothing measures is not a criterion.** Where a check exists
but has no caller, that is stated in its own column rather than hidden behind a tick.

---

## 1. 分模块 — modules with a declared identity

| # | Criterion | Checked by | Enforced? |
|---|---|---|---|
| 1.1 | Every source module belongs to exactly one declared layer | `scripts/layer-check.mjs` | **yes** — `clean: every cross-layer edge is declared` |
| 1.2 | Every dependency edge is declared, and every declared edge is used | `scripts/layer-check.mjs` | **yes** |
| 1.3 | Every suite on disk is named by a script | pre-flight `test wiring`, `claims` | **yes** — reported, not silently ignored |
| 1.4 | Every document's claim about the artifact matches the artifact | `test/claims.test.mjs` | **yes** — 48 claims, and it has caught real drift |
| 1.5 | No module is unreachable — every declared thing has a caller | *nothing* | **NO — see §4** |

`1.5` is the row that matters most and is the one **not** satisfied. This span shipped three mechanisms that
were, for a round each, fully tested and completely uncalled: `field-authority.mjs`, `approval-gate.mjs`, and
before them `createApprovalIndex`. **A tested mechanism with no caller is indistinguishable from a finished
feature by reading either the tests or the source.** `1.4` catches *documentation* drift and cannot catch this,
because the document and the code can agree while neither is reachable.

## 2. 分层级 — layers, with a direction

| # | Criterion | Checked by | Enforced? |
|---|---|---|---|
| 2.1 | Ranked layer model, declared as data | `scripts/layer-model.mjs` | **yes** |
| 2.2 | An allow-list of edges, not a denylist | `layer-model.mjs` | **yes** — a new edge is refused and forces a decision |
| 2.3 | No upward edge | `layer-check.mjs` | **yes** — it refused `agent → relay` in 0.30.0 |
| 2.4 | The layer a module sits in matches what it uses | `layer-check.mjs` | **yes** — it is how `SlidingWindowRateLimiter` was found mis-layered |

**`2.3` and `2.4` have each caught a real defect in this span**, which is the only evidence that a check is
worth its place. `2.3` fired when the approval gate reached for a relay module; the fix was to move the shared
limiter down to `util`, **not** to add the edge.

## 3. 分权限 — declared capabilities, and something that consults them

| # | Criterion | Checked by | Enforced? |
|---|---|---|---|
| 3.1 | Capabilities declared with a cost and a destructiveness flag | `authority.mjs` (`CAPABILITIES`) | **yes** |
| 3.2 | Every declared capability is reachable by some band | `auditCapabilities()`, asserted | **yes** |
| 3.3 | A decision is reached from a real dispatch's own facts | `gateDispatch`, `capabilityForDispatch` | **yes** |
| 3.4 | The dispatch path consults it | `tools.mjs`, asserted end to end | **yes** — since 0.23.0 |
| 3.5 | An undeclared capability is refused, not granted or escalated | `permission.test.mjs` | **yes** |
| 3.6 | Escalation is exactly one band | asserted across the whole table | **yes** |
| 3.7 | Nothing destructive auto-settles, at any level | `mayAutoSettle`, asserted | **yes** |
| 3.8 | An escalated dispatch reaches a queue an approver can answer | `w2m_approvals`, asserted end to end | **yes** |
| 3.9 | The queue's front door meters **raising only** | `approval-gate.mjs`, wired in 0.31.0 | **yes** |
| 3.10 | Field-level memory acceptance is driven by the same model | `field-authority.mjs` | **mechanism yes, caller NO — see §4** |
| 3.11 | **The gate is ON by default** | *nothing — it is off* | **NO — see below** |

### `3.11` is the load-bearing gap, and it is a decision rather than an oversight

`actorAuthorityLevel` is **unset by default**, and an unset level means the gate reports `enforced: false` and
changes nothing. So today, **a default install dispatches exactly as it did before the permission model
existed.** The reasoning is in `permission.mjs` and it is sound as far as it goes: treating an unset level as
`0` would refuse every writing dispatch on every machine that never opted in, breaking a working fleet to
enforce a policy nobody asked for.

**But "off unless configured" cannot be part of a 1.0.0 that claims 分权限**, because a permission system that
is off is a permission system that is untested in production. The question this file puts to a reader is
therefore concrete:

> **Should 1.0.0 require `actorAuthorityLevel` to be set, refusing to start without one — or should it ship
> with the gate off and say so in the README?**

Both are defensible. Silence is not, and neither is claiming 分权限 while it is off.

## 4. What is explicitly NOT claimed

Recorded here so that absence is a decision rather than an omission:

| Not claimed | Why |
|---|---|
| **Reachability of every module** | nothing measures it (§1.5). Three uncalled mechanisms were shipped in this span. |
| **The gate is active** | `actorAuthorityLevel` is unset by default (§3.11). |
| **Field authority reaches the memory layer** | `field-authority.mjs` has no production caller; `w2m_memory` does not use it. |
| **The queue survives a restart** | it is per-plugin-lifetime by design, and is **not** an audit log. |
| **Any scale claim** | this fleet is 3 usable machines of 5 paired. `ROADMAP.md` refuses to plan v4.11.0+ for exactly this reason, and `fleet-scale.mjs` refuses to extrapolate from five. |
| **MacMini verification of everything** | four suites were verified on that machine in 0.28.0; the other 69 were not. **Measured in 0.32.0: the eight suites tried there did not pass, and the cause is not yet established.** |
| **The eight suites tried on MacMini in 0.32.0** | every one of them returned non-zero there while passing here. The likely cause is a missing `node_modules` on that machine, but **that was not measured**, so it is a hypothesis and not a finding. |
| **`P2P_PUNCH_FAILED`** | cause UNVERIFIED; three hypotheses measured and excluded. |

## 5. What would make this file finished

1. **A reachability check** — every exported function has a non-test caller, or is declared as
   interface-only with a reason. Without it, §1.5 stays open and the class of defect that produced three
   dead mechanisms stays invisible.
2. **A decision on §3.11**, whichever way it goes, reflected in `README.md` and in the pre-flight.
3. **Every row above promoted to a check that runs**, so this document becomes a description of the
   pre-flight rather than a parallel list that can drift from it. **A document that restates what the
   pre-flight does is a second source of truth, and this project has already paid for one of those.**

This draft deliberately stops short of those three, because each is a decision about what 1.0.0 must be
rather than a defect to fix, and the person who owns it has not answered the question this session asked in
round 12: **write the acceptance definition, or keep advancing the roadmap?**
