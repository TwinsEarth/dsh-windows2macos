# ADR 0001 — 多机协作：本周期不引入 CRDT（D5）

- 状态：已接受（2026-10-28）
- 决策者：项目负责人（D5）
- 相关：D1=c、A6 项目房间、A7 聊天 AEAD、S4 数据面红线

## 背景

“多机跨机实时协作”的讨论中出现了共享编辑/多光标/实时文档（CRDT）诉求。当前系统的协作对象是：

- 追加式的编队聊天消息（`w2m_chat`）；
- 追加式的项目房间事件（board/locks/reviews/notifications）；
- 以 git 为权威的代码产物（patch/commit/merge）。

以上都是**追加式或 git 语义**，不是“多写者并发编辑同一份可变文档”。仓库同时保持 **零运行时依赖**、单文件手写 client bundle（无 bundler），以及“数据面不经 relay”的红线。

## 决策

**本周期（v2.x）不引入任何 CRDT 实现，不新增 CRDT 依赖，不写共享编辑代码。** 共享编辑若未来立项，必须先有新的 ADR 批准，并通过独立评审。

## 评估过的选项

| 选项 | 许可（本轮核实口径） | 体积/运行时 | 结论 |
|---|---|---|---|
| Yjs | MIT（npm 13.6.33） | 纯 JS，约 1MB+ 生态；需要 provider/transport | **未来首选**（若共享编辑立项，风险最低） |
| Automerge | MIT（npm latest 2.0.0-alpha.3） | Rust/WASM，数 MB，alpha 版本 | **备选**（需要 Git-like change DAG 证据时再评估） |
| json-joy | **AGPL-3.0-only**（多数包） | 2.2MB + 20+ 运行时依赖 | **明确排除**：与 MIT 公开插件分发不兼容，不依赖、不复制代码 |

## 不引入的理由

1. **问题形态不匹配**：当前协作是追加事件 + git 合并，CRDT 解决的是并发可变文档；引入它不会自动闭合 A3/A6 的任何缺口。
2. **零依赖是发布资产**：任何 CRDT 库都会进入持有 device token / operator key / fleet key 的进程信任域，扩大 CVE 面并破坏可复现的单文件打包。
3. **数据面红线**：共享编辑内容属于数据面，必须经用户 sink/git，不能经 relay；现有 relay 冻结，无法承载新的同步协议。
4. **权限与审计模型未定义**：多人同时编辑需要用户级身份、逐操作授权与审计，当前只有机器级身份。
5. **许可风险**：json-joy 为 AGPL，直接排除；Yjs/Automerge 需在立项时做人工法务复核。

## 触发条件（满足才可重新评估）

- 出现真实的“多人同时编辑同一份文档/文件”需求，而非代码补丁协作；
- 新的 ADR 获批，且明确数据面走 sink/git 或加密 P2P，不经 relay；
- 完成用户级身份、逐操作授权、审计与回滚设计；
- 选定单一实现（Yjs 优先），完成构建管线与许可复核，并接受依赖体积/供应链评审。

## 本周期替代方案

- 代码协作：git worktree + `git apply --3way` + CAS 更新目标分支（merge-engine，A4 CLI 已落地）。
- 产物同步：用户授权的 dir/git/ssh sink（A3）。
- 状态同步：项目房间事件 + 分页/截断信号（A6 截断已落地；持久化与客户端面板在后续切片）。
- 消息加密：聊天 AEAD v2 + AAD 会话/发送者绑定（A7）。

## 后果

- 不新增依赖，`package.json#dependencies` 保持为空；
- 不新增 `src/util/crdt.mjs` 之类的占位模块，避免制造“已有 CRDT”的读感；
- 未来若立项，按触发条件重新走 ADR，而不是在既有事件/合并路径上静默引入。

## 回滚/复审

纯文档决策，无运行时代码；复审时新增一份 ADR 取代本文件，并在 CHANGELOG 记录决策变化。
